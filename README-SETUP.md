# Analytics4 CMS: safe installation

## Before anything: protect your work
Create a backup branch in GitHub, or download a repository ZIP. Do not run the old "Import original blog (manual)" after adopting the CMS: it writes the same HTML/JSON files and can overwrite CMS changes.

## 1. Add the three files to the root of your existing repository
- `.pages.yml`
- `cms_blog.py`
- `.github/workflows/publish-cms-blog.yml`
Keep all existing files intact. GitHub's browser upload does not reliably preserve folders: create the paths using Add file > Create new file, or upload via a Git client.

## 2. Initial migration (one-time, before using the CMS)
Run the following in a local clone of your existing repository, with Python installed:

    python -m pip install beautifulsoup4 markdown markdownify pyyaml requests
    python cms_blog.py bootstrap

This creates one Markdown file for each existing language version from `content/blog_languages.json` and DOES NOT overwrite any existing Markdown files. Review the results in `content/posts/it`, `en`, `pl` and commit those generated Markdown files. Keep the original JSON and HTML files until you have confirmed the new pages look correct. If some language versions are wrong, remove the incorrect Markdown files before the first publish.

Alternatively, to avoid a local Python setup, temporarily add the included `bootstrap-cms-blog.yml` workflow, run it ONCE from GitHub Actions, inspect the generated Markdown files, then delete/disable the bootstrap workflow.

## 3. First publish
Go to Actions > Publish CMS blog > Run workflow. Wait until the run completes and Pages updates. Check `/Blog/it/`, `/Blog/en/`, `/Blog/pl/`, and homepage cards. If the archive or article layout is not what you want, restore the backup before editing further.

## 4. Editor
Go to https://app.pagescms.org/ > Sign in with GitHub > authorize the app for DragonKrakow/analytics4 > choose main. Three language collections should appear. Edit a post or create one; save it. The GitHub Action will rebuild the pages automatically. Uncheck Published to hide a post; delete the Markdown file from the editor to remove it from the generated feeds and pages on the next build. Only published versions appear in that language's archive.

## Important limitations
- No automatic translation; each language version is a separate article.
- The original import workflow is not compatible with the CMS. Disable it after successful migration.
- Existing image references are preserved as far as possible, but visually review imported posts; complex original HTML may not convert perfectly to Markdown.
- CMS publishing removes only HTML pages previously generated by this CMS. Pre-existing legacy article HTML pages may remain as orphan URLs after deletion; clean them manually after reviewing the site.
- The sample media output assumes GitHub Pages base path `/analytics4/`. If you later move to a custom domain root, adjust `.pages.yml` and media paths.
